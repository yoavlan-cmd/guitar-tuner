# Daily scheduled job — "Guitaring daily song ideas"

- **Runs:** every day 05:51 Asia/Jerusalem (`CRON_TZ=Asia/Jerusalem 51 5 * * *`), as a cloud Claude session in auto-approve mode.
- **Connectors it needs:** Google Drive (search_files), GitHub (add_repo: push access to `guitar-tuner` and to the private `guitaring-split`), web search.
- **Reads (privacy step B, Oct 2026):** `profile.json` in the private `guitaring-split`, written by the app when My profile › "Use my profile for daily ideas" is on: the profile answers and the songs with their status (Learning, Learned, Idea for later) and since when. Without the file the job works as before. Nothing from it goes into the public `ideas.json`.
- **Output:** a commit of `ideas.json` to the repo root (served next to `index.html` by GitHub Pages) and, since privacy step C (Oct 2026), the same file committed to the root of the private `guitaring-split` (its default branch), which the app reads when GitHub is connected. The public copy stays until step D. The job writes nothing else to `guitaring-split`.
- **Blocker as of V1:** pushing needs the Claude GitHub App installed on `yoavlan-cmd/guitar-tuner`. Until then the run stops at step 6 and the user uploads `ideas.json` by hand.

The prompt below is the exact text the job sends every morning. Keep it in sync with `tools/ideas_build.py`.

---

Daily job for Yoav's guitar app "Guitaring" (GitHub repo yoavlan-cmd/guitar-tuner, served on GitHub Pages at https://yoavlan-cmd.github.io/guitar-tuner/). Goal: scan his Google Drive songs folder, list the chord sheets made with Guitaring, pick ~10 new songs for him to learn, every second day add a few new welcome-screen jokes, and publish it all as ideas.json in the repo so the app shows them automatically. Work unattended; don't ask questions.

1. Get the repo: use the add_repo tool for owner "yoavlan-cmd", repo "guitar-tuner" with access "push", then clone it (git clone --depth 1 https://github.com/yoavlan-cmd/guitar-tuner /home/claude/gt) and cd into it. The helper script is ideas_build.py at the repo root (or tools/ideas_build.py); always run it from the repo root. Run `python3 ideas_build.py context` to see the songs from the last scan, every song suggested before, whether welcome jokes are due today, and the jokes the app already has. If the script isn't in the repo, stop and report that.

1b. Get his profile (private): use the add_repo tool for owner "yoavlan-cmd", repo "guitaring-split" with access "push" (needed in step 6b), then clone it (git clone --depth 1 https://github.com/yoavlan-cmd/guitaring-split /home/claude/gs) and read /home/claude/gs/profile.json if it exists. Never change profile.json or any other file there; the only write to that repository is ideas.json in step 6b. If add_repo or the clone fails, or there's no profile.json, carry on without it (everything below works as before) and say so in the summary. The file has his answers (level, years, skills, instruments, capo "yes"/"no", genres, artists, dreamSongs, goals, songLang "he"/"en", time, context) and "songs": [{t, a, status ("learning" | "learned" | "idea"), since (when the status last changed, or when the song was added), opened (when he last opened it), chords, capo}].

2. Scan Drive with the Google Drive connector's search_files tool. Songs folder id: 1oQhXOTPCngexgTdH8WuG4RLikLSs6XMe. Inside it, each subfolder is an artist; files inside are songs (Google Docs, PDFs, sometimes videos).
   - List the folder: query `parentId = '1oQhXOTPCngexgTdH8WuG4RLikLSs6XMe'`, excludeContentSnippets true, pageSize 100, follow nextPageToken until there is none. Remember each artist folder's id and name.
   - For the artist folders, query in groups like `parentId = 'A' or parentId = 'B' or parentId = 'C'` with snippetVerbosity "BRIEF" and follow every nextPageToken (pages with snippets are small, so keep paging). Also include song files sitting directly in the main folder.
   - From each file's contentSnippet, read the chord names on the chord lines (e.g. Am, F#m, Bb4, Dsus2, G/B; in snippets "F\#m" means F#m and "F\#ᶥ" means F#m). Note a capo ("Capo fret 1") or a non-standard tuning ("Drop D") if the snippet says so. Skip tablature digits and lyrics.
   - Write /tmp/index.json: {"artists": [every artist folder name, even empty ones], "songs": [{"a": artist folder name ("" for files in the main folder), "t": the file title exactly as in Drive, "ch": [chords], "capo": number (optional), "tuning": "Drop D" (optional)}]}. The script cleans names (extensions, "Artist - Song", untitled docs).

3. Find the sheets made with Guitaring (anywhere in his Drive): search_files with query `mimeType = 'application/pdf' and (fullText contains 'Guitaring' or fullText contains 'LYRICS & CHORDS' or fullText contains 'PROGRESSION')`, snippetVerbosity "BRIEF", pageSize 50, following every nextPageToken. Write /tmp/sheets.json as a JSON list with one object per file: {"title": file title, "viewUrl": its viewUrl, "createdTime": its createdTime, "folder": the artist folder name if its parentId is one of the artist folders from step 2 (else omit), "contentSnippet": the part of the snippet up to and including the line "LYRICS & CHORDS" or "PROGRESSION", plus any later lines that contain only chord names}. Copy the snippet text faithfully (the script reads "Artist …", "Tuning …", "Capo …" and the chord names from it).

4. Choose the ideas yourself (you are the music expert). Base them on the artists, styles and chords in the folder, and on his profile when step 1b found one.
   LEVEL, with a profile: his song statuses show his progress. Learned songs (the newer ones count most) are what he can play: their chords, capo use and difficulty set his level. Learning songs are his current step: stay close to them. If most Learning songs have been Learning for 4+ weeks (since) and nothing was marked Learned lately, don't raise the level: suggest songs that practise the chords of those Learning songs instead. Ideas for later show taste only, not level. His stated level is a starting point; with 3 or more Learned songs, the statuses win. If he has no Learned songs (statuses never updated), use his stated level together with the chords in the folder. TASTE, with a profile: his genres, artists and dream songs come first (a dream song close to his level is a good pick, as a step up); songLang sets the Hebrew/English mix; if capo is "no", prefer songs played without one; follow his goals (e.g. campfire: sing-along songs). Never suggest a song that is in his profile's songs (any status).
   Without a profile: level = what the chords show he can already play; mostly suggest songs at about his level, plus 2–3 that are a small step up (1–2 new chords or one new technique) and 1–2 easier ones. Mix Hebrew and English, roughly in the proportion of the folder. Include a few songs by artists he already has (empty artist folders are a hint he wants that artist) and several by similar artists he doesn't have yet. Only real, well-known songs; Hebrew songs with Hebrew title and artist names, spelled exactly as chord sites spell them. Never repeat a song from his folder or from the "suggested before" list. For chords, give the common simple version that chord sites show; if you're not sure of a song's chords, use an empty list rather than guessing.
   PRIVACY: ideas.json is public. Don't copy anything from profile.json into it: the "level" sentence and each "why" stay general (no statuses, dates, goals or other answers).
   VERIFY EVERY SONG before using it (this matters most for Hebrew songs; a made-up title once slipped through): run a web search such as `<title> <artist> אקורדים` or `<title> <artist> chords`, and keep the song only if a chord or lyrics site (tab4u, nagnu, shironet, Ultimate Guitar, songish) shows that exact title by that artist. If it can't be confirmed, or the site spells it differently, drop it or use the spelling the site uses. Then write /tmp/sugg.json: {"level": one short sentence about his current level, "suggestions": [10 items of {"title","artist","style" (short genre label),"difficulty" (1–5),"chords":[...],"capo": number or 0,"tuning":"Standard" or the tuning,"why": one short sentence on why it fits him and what's new to learn}]}.

5. Run `python3 ideas_build.py write /tmp/index.json /tmp/sugg.json /tmp/sheets.json` from the repo root. If it rejects songs or says there are too few, replace the rejected ones in /tmp/sugg.json (verified the same way) and run it again until it writes ideas.json.

5b. Welcome jokes (only if step 1 printed "Welcome jokes due today: YES"): write 4 new jokes for the app's welcome screen, in English, in the same voice as the listed ones: short, playful, lightly sarcastic nudges to practise guitar, where {n} stands for his first name. Themes: guitar life, practising, chords, strings, gear, neighbours, and famous guitarists and bands (international and Israeli). Keep them good-natured: no family, health, work, money, politics or religion, nothing crude, and nothing that could read as a real quote or a real insult from a real person. Each 40–180 characters, with {n} exactly once, and not a repeat or rephrase of any listed joke. Save them as a JSON list of 4 strings in /tmp/jokes.json and run `python3 ideas_build.py jokes /tmp/jokes.json` from the repo root (after step 5). If it rejects some, replace them and run it again.

6. Commit only ideas.json with the message "Daily song ideas YYYY-MM-DD" (today's date in Israel), ending the message with the line "Co-Authored-By: Claude <noreply@anthropic.com>", and push to main. If the push is refused because the Claude GitHub App isn't installed on the repo, stop and report exactly that.

6b. Private copy: copy the same ideas.json to the root of /home/claude/gs (the guitaring-split clone from step 1b), commit only that file with the same message, and push to that repository's default branch (git -C /home/claude/gs push origin HEAD). If step 1b couldn't clone it, or the push is refused, don't retry anything else: the public copy from step 6 still serves the app; say so in the summary.

Finish with a short summary: whether profile.json was used (and if not, why), whether the private copy of ideas.json was pushed, how many artists/songs were scanned, how many Guitaring sheets were listed, the 10 songs suggested (and any you dropped because they couldn't be verified), and the new jokes if any were added. Don't change any other file in either repository: only ideas.json is written, to guitar-tuner and to guitaring-split.
